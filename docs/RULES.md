# My Fortune 第一版推荐规则

规则版本 `daily-theme-v4`，提示词版本 `fortune-v4`。

此版本是可执行的娱乐内容方法，分数和映射由本项目定义。它采用明确的干支关系及五行主题，不执行完整旺衰、格局、调候或喜用神推断。出生资料相同可以得到相同推荐；不追求人与人之间绝对唯一。

## 计算依据

Python 实现参照 taibu-core 4.1.0 的公农历、节气、时区、四柱、十神、藏干、黄历与干支关系口径，使用 lunar-python 与 Python astronomy-engine。日运查询固定以澳门日期计算。关系工具同时返回大运、流年、流月、流日及与原局的关系。上游规则全文位于 `vendor/taibu-core/ALGORITHM_RULES.md`。

出生时间使用出生地时区，日期输入当前为公历。出生日期、性别、出生时区齐全时计算命盘；未知小时只排三柱。资料不齐标记 general，提供一般当日主题。交节等上游无法确定的边界会失败并留待补资料，不悄悄伪造命盘。

## 每日五行规则

天干五行按甲乙木、丙丁火、戊己土、庚辛金、壬癸水。

- 当日日干五行加 2 分。
- 有个人日主时，其五行加 2 分，生扶它的五行加 1 分。
- 相生关系为木生火、火生土、土生金、金生水、水生木。
- 同一五行的分数累加，选总分最高者。
- 平分时按木、火、土、金、水的顺序排列，再用目标日期序数对并列数量取余，选择其中一个。
- 资料不足时只使用当日日干五行，因此该五行直接入选。

例如日主庚金、当日日干戊土，金得 2 分，土得到日干 2 分与生金的 1 分，共 3 分，选择土。

日运上下文只保留 `{"element": "earth"}`，数字、颜色和目录评分共用。候选分数和选定五行保存到 audit_json，供核对与复现。当前计分覆盖同五行与相生，后续可扩展相克因素。

这些权重是本项目第一版产品规则。Qwen 每位客人调用两次，分别选择物品和餐厅。已有成功记录继续按客人及日期复用。

## 今日生肖

候选为十二生肖。分别与当日地支、出生年支、出生日支比较，六合 +3、同属三合组且不同支 +2、六冲 -4、其他 0。同支本身不加分。

当日地支的权重为 2，出生年支和日支各为 1。排除与当日地支六冲的候选，取总分最高者。并列时按日期序数轮换，规则只提供娱乐意义的“今日相合生肖”。当前没有生肖到 Lucky 6 等具体玩法的映射。

## 今日数字

主题五行对应两枚数字，按日期序数奇偶轮换。

| 五行 | 数字 |
| --- | --- |
| 水 | 1、6 |
| 火 | 2、7 |
| 木 | 3、8 |
| 金 | 4、9 |
| 土 | 5、0 |

数字 0 是本产品对土主题数字 10 的单数字化配置。

## 今日颜色

| 五行 | 颜色 |
| --- | --- |
| 木 | Green、Jade |
| 火 | Red、Purple |
| 土 | Yellow、Brown |
| 金 | Gold、White |
| 水 | Blue、Black |

根据选定五行取得两个主题色，再按日期序数轮换。颜色只依赖日运五行和目标日期。色值在 lucky_color.py 中固定。

## 今日物品与餐厅

先由 SQL 取 active=true 的目录。目录 metadata 约定如下，标签应由运营维护，拼写一致。

```json
{
  "elements": ["metal"],
  "colors": ["gold"],
  "materials": ["gold"],
  "category": "jewelry"
}
```

餐厅可以使用以下标签。elements 属于运营主题标签。

```json
{
  "elements": ["fire"],
  "colors": ["red"],
  "cuisine": "sichuan",
  "allergens": ["peanut"],
  "dietary_options": ["vegetarian"]
}
```

当前从 active=true 的目录中按主题五行匹配 +5、当日颜色匹配 +2 排序。按分数降序、目录 ID 升序，取前 20 个候选交给 Qwen。

Qwen 结合个人日运、当日颜色和目录标签选择一个 ID，并返回理由。程序校验 ID 必须属于提供给模型的候选，理由保存在 audit_json.catalog_decisions。没有有效候选时该客人本次生成失败。

当前版本只使用出生资料、日运和目录标签。个人偏好、过敏及饮食限制等 preferences 逻辑已移除，已有目录里的附加标签作为目录描述保留。

## 发布与复现

五项全部成功才写入 my_fortunes。审计字段保存实际排盘、日运、主题候选与规则版本。历史结果缺少 rules_version、personalization 时兼容读取。已有成功结果默认不会因为重跑或规则升级而覆盖。


固定 SQL 测试结果仍使用生成时的确定性排名，标记 fixture-no-llm。运行 app.seed --with-llm 或 app.precalculate 才走当前真实模型生成流程。
