# My Fortune 第一版推荐规则

规则版本 `daily-theme-v7`，提示词版本 `fortune-v5`。

此版本是可执行的娱乐内容方法，分数和映射由本项目定义。它采用明确的干支关系及五行主题，不执行完整旺衰、格局、调候或喜用神推断。出生资料相同可以得到相同推荐；不追求人与人之间绝对唯一。

## 计算依据

Python 实现参照 taibu-core 4.1.0 的公农历、节气、时区、四柱、十神、藏干、黄历与干支关系口径，使用 lunar-python 与 Python astronomy-engine。日运查询固定以澳门日期计算。关系工具同时返回大运、流年、流月、流日及与原局的关系。上游规则全文位于 `vendor/taibu-core/ALGORITHM_RULES.md`。

出生时间使用出生地时区，日期输入当前为公历。出生日期、性别、出生时区齐全时计算命盘；未知小时只排三柱。资料不齐标记 general，提供一般当日主题。交节等上游无法确定的边界会失败并留待补资料，不悄悄伪造命盘。

## 每日五行规则

天干五行按甲乙木、丙丁火、戊己土、庚辛金、壬癸水。

当前采用固定的**生扶策略**，入口为 `app.rules.daily_element_decision(facts)`，由 `FortuneService.generate()` 第 5 步调用。输入是个人日主天干与当天日干，不执行旺衰或喜用神判断。当天五行均由日干取得，不使用地支本气替换。

相生关系为木生火、火生土、土生金、金生水、水生木；相克关系为木克土、土克水、水克火、火克金、金克木。

| 当天五行与日主关系 | 推荐方向 | 丙火日主：当天 → 推荐 | 产品解释 |
| --- | --- | --- | --- |
| 生我 | 生我五行 | 木 → 木 | 延续当天的生助方向 |
| 同我 | 日主五行 | 火 → 火 | 采用同类帮助日主 |
| 我生 | 生我五行 | 土 → 木 | 当天形成泄，以生我五行补充支持 |
| 我克 | 日主五行 | 金 → 火 | 当天形成消耗，以同类帮助日主 |
| 克我 | 生我五行 | 水 → 木 | 采用水生木、木生火的相生链条作为缓和方向 |

这张表按相对关系推广至五种日主。例如庚金日主、当日日干戊土，属于土生金，选土；丙火日主、当日日干戊土，属于火生土，选木。缺少个人日主时，返回 `strategy=general`，直接采用当天日干五行，不作个人生扶判断。

本版删除了日干 +2、日主 +2、生我 +1 的候选评分，以及最高分、平分日期轮换。没有随机选择“生扶 / 制约”，也不做权重抽选或分布均衡。制约分支尚未定义和实现。

日运上下文继续只保留 `{"element": "wood"}`，数字、颜色和目录评分共用。`element_decision` 另保存策略、日主五行、当天五行、关系代码、推荐五行和中文理由，同时传给 Qwen，并持久化至 `audit_json.element_decision`。这取代旧版 `theme_candidates` 分数列表。

关系代码：`generates_master` 生我、`same` 同我、`generated_by_master` 我生、`controlled_by_master` 我克、`controls_master` 克我。

本版生扶是约定的产品方向，不代表每个人都需要生扶，也不是完整的传统取用判断。Qwen 每位客人仍调用两次，分别选择物品和餐厅。已有成功记录继续按客人及日期复用，不会因规则升级自动覆盖。

## 今日生肖

入口为 `app/recommendations/lucky_zodiac.py` 的 `generate(context)`，由 `FortuneService.generate()` 第 7 步调用。v7 用**个人四支的六合生肖作候选，当天负责筛选**，替代旧版地支加权评分。与生扶五行决策独立。

| 步骤 | 条件及处理 |
| --- | --- |
| 个人候选 | 对已知的年、月、日、时支分别取六合伙伴，合并去重。未知时支跳过；四支同等参与，重复地支不增加权重 |
| 当天避冲 | 排除与当日日支六冲的候选。个人其他柱的六冲不作为硬排除 |
| 扩展兜底 | 若所有个人六合候选都被排除，扩展到个人四支同属三合组的其他伙伴，去重并再次排除当天六冲 |
| 当天优先 | 剩余候选中，与当天六合、或同属三合组且不同支的候选享有同等优先级；没有“当天六合必胜” |
| 稳定轮换 | 在优先候选中选择；若没有优先候选，则从全部剩余候选中选择。按子丑寅卯辰巳午未申酉戌亥排序，使用目标日期序数对候选数量取余。一个候选直接入选，无随机抽签 |
| 无个人命盘 | 没有已知个人地支时，直接采用当天的六合生肖，标记来源 `daily_combine`，不伪造个人候选 |

六合：子丑、寅亥、卯戌、辰酉、巳申、午未。三合组：申子辰、亥卯未、寅午戌、巳酉丑。六冲：子午、丑未、寅申、卯酉、辰戌、巳亥。这里只使用“同属三合组”关系，不推断三合化局。

例如虚构个人四支为亥、丑、未、戌，六合候选为寅、子、午、卯。2026-11-20 为戌日，四个候选都不与当天六冲；卯与当天六合，寅、午与当天同属寅午戌三合组，三者同等优先。该日期序数为 739940，对按地支顺序排列的寅、卯、午取余，选择午（Horse），不会因为卯是当天六合就直接选卯。

生肖模块将个人地支、每柱的六合候选来源、初始候选、排除候选、扩展候选、最终候选池、日期轮换索引、选定地支及中文理由存入 `context.zodiac_decision`。该数据传给 Qwen，并保存至 `audit_json.zodiac_decision`。`payload.lucky_zodiac` 仍为原有英文生肖枚举，REST 响应格式和表结构不变。

候选来源为 `personal_combines`（个人六合）、`personal_trines`（扩展个人三合组伙伴）、`daily_combine`（无命盘的一般主题）。选择顺序属于产品规则，不保证所有生肖均匀出现，也不保证人与人之间唯一。当前没有生肖到 Lucky 6 等具体玩法的映射。

## 今日数字

主题五行对应两枚数字，按日期序数奇偶轮换。

| 五行 | 数字 |
| --- | --- |
| 水 | 1、6 |
| 火 | 2、7 |
| 木 | 3、8 |
| 金 | 4、9 |

数字 0 是本产品对土主题数字 10 的单数字化配置。

## 今日颜色

| 五行 | 颜色 |
| --- | --- |
| 木 | Green |
| 火 | Red、Purple、Orange、Pink |
| 土 | Yellow、Brown |
| 金 | Gold、Silver |
| 水 | Blue |

以上分组为产品配置，使用 Red、Blue、Purple、Green、Yellow、Gold、Silver、Orange、Brown、Pink 共 10 种颜色。

根据选定五行取得对应颜色组，再按日期序数对组内数量取余进行轮换。木、水各一个颜色，固定返回；火有四种，按四天轮换；土、金各两种，按日期奇偶轮换。颜色只依赖日运五行和目标日期。色值在 lucky_color.py 中固定。

## 今日物品与餐厅

先由 SQL 取 active=true 的目录。目录 metadata 约定如下，标签应由运营维护，拼写一致。

```json
{
  "elements": ["metal"],
  "colors": ["gold"],
  "materials": ["gold"],
  "category": "jewelry"
}
```

餐厅可以使用以下标签。elements 属于运营主题标签。

```json
{
  "elements": ["fire"],
  "colors": ["red"],
  "cuisine": "sichuan",
  "allergens": ["peanut"],
  "dietary_options": ["vegetarian"]
}
```

当前从 active=true 的目录中按主题五行匹配 +5、当日颜色匹配 +2 排序。按分数降序、目录 ID 升序，取前 20 个候选交给 Qwen。

Qwen 结合个人日运、当日颜色和目录标签选择一个 ID，并返回理由。程序校验 ID 必须属于提供给模型的候选，理由保存在 audit_json.catalog_decisions。没有有效候选时该客人本次生成失败。

当前版本只使用出生资料、日运和目录标签。个人偏好、过敏及饮食限制等 preferences 逻辑已移除，已有目录里的附加标签作为目录描述保留。

## 发布与复现

五项全部成功才写入 my_fortunes。审计字段保存实际排盘、日运、生扶决策、生肖候选及选择依据、规则版本。历史结果缺少 rules_version、personalization 时兼容读取。已有成功结果默认不会因为重跑或规则升级而覆盖。


固定 SQL 测试结果仍保留生成时的 v5 主题评分及确定性目录排名，标记 fixture-no-llm；它们是历史样例，不代表当前 v7 结果。仓库内既有演示文稿也保留旧版评分示例，当前可执行规则以本文为准。v7 保留 v6 生扶表，更新生肖算法。运行 app.seed --with-llm 或 app.precalculate 对尚未保存的客人及日期才走当前 v7 生成流程。
